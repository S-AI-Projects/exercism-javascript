# Eliud's Eggs: Implementation Approach Comparison

## 1. Overview

This document compares the maintained reference implementation with a genuinely different alternative approach for the **Eliud's Eggs** exercise (`exercises/practice/eliuds-eggs`).

The task requires counting the number of `1` bits in the binary representation of a non-negative decimal integer (`displayValue`), representing egg-laying spots where an egg is present.

---

## 2. Approach Descriptions & Representations

### Approach A: Binary String Conversion & Array Reduction (Reference)

- **Source**: `exercises/practice/eliuds-eggs/.meta/proof.ci.js`
- **Data Representation**:
  - The decimal integer is converted into a binary ASCII text string (`displayValue.toString(2)`).
  - The string is spread into an array of 1-character strings (`[...str]`).
- **Control Flow**:
  - Declarative functional pipeline using `Array.prototype.reduce`.
  - Iterates over each character in the array and accumulates `1` whenever `curr === '1'`.
- **Complexity**:
  - **Time Complexity**: $\mathcal{O}(B)$ where $B = \lfloor \log_2(N) \rfloor + 1$ is the number of bits in the binary representation ($B \le 31$ for values in the exercise).
  - **Space Complexity**: $\mathcal{O}(B)$ auxiliary heap memory to store the intermediate string and array.

### Approach B: Direct 32-bit Numeric Bitwise Manipulation (Alternative)

- **Source**: `work/R53-T046/alternative.js`
- **Data Representation**:
  - Operates directly on the primitive number as a 32-bit unsigned binary integer in CPU registers.
  - Zero heap allocations, zero string conversions, zero array wrappers.
- **Control Flow**:
  - Imperative `while` loop that terminates when the remaining value reaches `0`.
  - In each iteration:
    - Tests the least significant bit with bitwise AND (`remaining & 1`).
    - Accumulates the bit value directly into the egg counter.
    - Shifts remaining bits one position to the right using the zero-fill right shift operator (`remaining >>>= 1`).
- **Complexity**:
  - **Time Complexity**: $\mathcal{O}(B)$ where $B = \lfloor \log_2(N) \rfloor + 1$ iterations. Each iteration executes single-cycle CPU instructions (`AND`, `ADD`, `SHR`).
  - **Space Complexity**: $\mathcal{O}(1)$ auxiliary space. Only scalar counter and loop variables on the stack.

---

## 3. Why the Approaches are Genuinely Different

| Aspect                          | Reference Approach                                                  | Alternative Approach                                        |
| :------------------------------ | :------------------------------------------------------------------ | :---------------------------------------------------------- |
| **Primary Data Representation** | High-level Text (`String`) & Heap `Array`                           | Primitive 32-bit Numeric Word (`Number`)                    |
| **Programming Paradigm**        | Declarative / Functional (`reduce`)                                 | Imperative / Procedural (`while` loop)                      |
| **Bit Evaluation Mechanism**    | Character equality comparison (`curr === '1'`)                      | Bitwise masking (`remaining & 1`)                           |
| **Bit Traversal Direction**     | Left-to-right (MSB to LSB as generated by `toString(2)`)            | Right-to-left (LSB to MSB via right shift `>>>= 1`)         |
| **Memory Allocation**           | Heap allocated string and array ($\mathcal{O}(B)$ space)            | In-place register/stack arithmetic ($\mathcal{O}(1)$ space) |
| **Runtime Dependencies**        | Relies on JavaScript V8 runtime string formatting & array iteration | Direct arithmetic & bitwise CPU instructions                |

## 4. Worked Example: 4 Eggs (Input: 89)

The decimal number `89` corresponds to binary `1011001` (7 bits, 4 ones).

### Reference Approach Execution:

1. `89.toString(2)` generates the string `"1011001"`.
2. Spread `[..."1011001"]` creates `['1', '0', '1', '1', '0', '0', '1']`.
3. `reduce` executes 7 times:
   - Index 0: `'1'` $\to$ acc = 1
   - Index 1: `'0'` $\to$ acc = 1
   - Index 2: `'1'` $\to$ acc = 2
   - Index 3: `'1'` $\to$ acc = 3
   - Index 4: `'0'` $\to$ acc = 3
   - Index 5: `'0'` $\to$ acc = 3
   - Index 6: `'1'` $\to$ acc = 4
4. Final return value: `4`.

### Alternative Approach Execution:

1. Initialize `count = 0`, `remaining = 89` (`0b1011001`).
2. **Iteration 1**:
   - `remaining & 1` = `89 & 1` = `1` $\implies$ `count` becomes `1`.
   - `remaining >>>= 1` $\implies$ `remaining` becomes `44` (`0b101100`).
3. **Iteration 2**:
   - `remaining & 1` = `44 & 1` = `0` $\implies$ `count` remains `1`.
   - `remaining >>>= 1` $\implies$ `remaining` becomes `22` (`0b10110`).
4. **Iteration 3**:
   - `remaining & 1` = `22 & 1` = `0` $\implies$ `count` remains `1`.
   - `remaining >>>= 1` $\implies$ `remaining` becomes `11` (`0b1011`).
5. **Iteration 4**:
   - `remaining & 1` = `11 & 1` = `1` $\implies$ `count` becomes `2`.
   - `remaining >>>= 1` $\implies$ `remaining` becomes `5` (`0b101`).
6. **Iteration 5**:
   - `remaining & 1` = `5 & 1` = `1` $\implies$ `count` becomes `3`.
   - `remaining >>>= 1` $\implies$ `remaining` becomes `2` (`0b10`).
7. **Iteration 6**:
   - `remaining & 1` = `2 & 1` = `0` $\implies$ `count` remains `3`.
   - `remaining >>>= 1` $\implies$ `remaining` becomes `1` (`0b1`).
8. **Iteration 7**:
   - `remaining & 1` = `1 & 1` = `1` $\implies$ `count` becomes `4`.
   - `remaining >>>= 1` $\implies$ `remaining` becomes `0` (`0b0`).
9. Loop terminates because `remaining > 0` is false. Final return value: `4`.

## 5. Trade-Offs and Analysis

### Readability & Expressiveness

- **Reference**: Very expressive for web developers who routinely chain array methods. It reads like "convert to binary, find all ones, count them".
- **Alternative**: More direct for developers familiar with systems programming or algorithms. It reflects the hardware reality of popcount / Hamming weight calculation.

### Performance & Memory

- **Memory**: The alternative is strictly zero-allocation ($\mathcal{O}(1)$), avoiding garbage collection pressure. The reference allocates a string of length $B$ and an array of $B$ elements for every function call.
- **CPU Time**: Bitwise operations execute in 1 clock cycle on modern processors, whereas string creation requires radix conversion, string buffer allocation, UTF-16 character creation, array object instantiation, and closure invocation per element.

### Domain Boundary

- Both approaches operate correctly for all non-negative integers up to $2^{31} - 1$ ($2,147,483,647$).
- All test suite cases (`0`, `16`, `89`, `2000000000`) fall within this range and produce identical, verified results.
